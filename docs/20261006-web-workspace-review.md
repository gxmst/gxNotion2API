# 网页工作区更新（2026-10-06）

## 日常使用

聊天、账号、会话、状态、模型和设置使用统一导航。新增账号放在独立弹窗。账号和设置编辑保留未保存草稿，离开时提示。

聊天右上角提供工作区模型、工作区笔记和额度入口。额度同时显示滚动和月度已用比例，滚动倒计时使用上游返回的截止时间，月度显示重置日期。没有返回时间时明确显示未知。倒计时在浏览器本地更新。

## Opus 5.5 与模型限制

抓包中的 Opus 5.5 标识是 albuquerque-quinn，选项仍以当前工作区动态目录为准。试用工作区可能没有聊天模型选择器；在“工作区模型”中读取策略，确认个人代理作用域，选择仅允许目标模型并应用，随后使用 Auto 聊天。自定义代理有独立策略。

策略影响工作区其他客户端，仅在用户明确应用时写入，不随每条消息自动切换。保留版本检查、恢复点和审计。限制策略不等同于证明实际使用了指定模型，应结合响应模型证据检查。

## 流式协议

本次抓包使用 patchResponseVersion 2。推理步骤可能首次出现于 patch-sync，随后使用绝对 /s/N 路径追加文本。旧解析器忽略快照帧，导致增量丢失，直到最终 record-map 才出现整段回答。

解析器现处理 patch-start / patch-sync，重建索引并保留已发送文本游标，避免重复输出。离线回放在最终记录前收到 239 个文本片段，拼接结果与最终回答一致。部署环境额外缓冲仍需实际验证。

可选回归：设置 N2A_TEST_HAR 为本地 HAR 路径，运行 go test ./internal/app -run TestCapturedStreamReplay -v。测试仅输出计数，不将抓包、凭证或正文写入仓库。

## 笔记范围和请求频率

笔记入口显式读取当前账号可访问的共享页面，列表不是工作区全部笔记。单页只读取一块内容，最多遍历 200 个块、12 层和约 12000 字文本；复杂结构、子页及未加载分页标为部分预览。引用将可见文本快照插入草稿，不自动发送，也不是 Notion 原生页面附件。编辑链接打开 Notion，本次未实现远程笔记写入。

额度沿用服务端缓存及刷新节流。笔记读取使用内存缓存、单次请求、超时和冷却，尊重 Retry-After，不自动登录重试或后台遍历工作区。这些措施减少请求量，不能保证上游不会限制账号。

验证使用 go test ./...、go vet ./...、前端生产构建及 Playwright 桌面/移动端回归。使用模拟 API 与离线 HAR，未执行真实 Notion 写入或线上部署验证。

## 二次审查：动态目录与别名

新增模型不需要追加固定名单。当前工作区上游目录返回后，重新读取模型设置即可显示；通用模型目录需要刷新模型能力。试用账号的聊天下拉框仍可能只有 Auto，这是上游权限限制。

设置页展示本次目录的官方名称、供应商、设置 ID 和当前代理作用域的 finalModelName。没有返回推理别名时显示未知，不猜测对应关系。别名指向多个模型时拒绝模糊解析，明确模型 ID 优先；显式配置可消除歧义。

模型策略使用禁用列表，同供应商新增模型可能成为新的候选，需要手动重新读取和应用。不会自动修改远程工作区。流式同步现在保留相同步骤此前报告的模型证据。笔记切换读取失败后清空旧预览，避免误引用。
