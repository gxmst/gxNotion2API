## 为什么会连续遇到问题

主要问题集中在浏览器临时状态、本地 SQLite 记录和 Notion 线程之间的衔接。正常发送成功不代表失败重试、历史导入、编辑删除也使用相同的消息 ID、账号归属和持久化路径。上游记录有单层、双层包装两种形态，原来的解析又散落在多处，只修一处会遗漏另一处。

既有前端测试主要使用固定形态的模拟接口。它们能覆盖界面操作，但无法代替真实协议变化及存储失败的验证。本轮因此新增了格式变体、数据库拒绝写入、缓存淘汰、流式失败后编辑删除等回归用例。

## 本轮审查确认并修复的问题

| 级别 | 触发条件与影响 | 修复与验证 |
| --- | --- | --- |
| P1 | 续聊后导入记录仍使用 `notion_thread:` ID。删除整个会话会误走远端专用分支，绕过本地清理和记录归属。 | 优先查本地记录，统一使用账号归属、删除占用锁及持久化清理；新增导入会话删除回归。 |
| P1 | SQLite 写入失败时，编辑/改名/单条删除先改内存，再吞掉存储错误，接口仍返回成功。 | 按快照相同的锁顺序保存；存储成功后才替换内存并广播，失败返回 500 且不改变原记录。三个接口均通过数据库触发器模拟拒写验证。 |
| P2 | 图片或文字发送失败后，浏览器仍显示临时消息 ID；紧接着编辑、删除会报消息不存在，图片也从待发送区消失。 | 失败及停止后重新读取服务端消息身份；保留可见的较长部分回答，恢复失败请求的附件。桌面/手机均验证失败图片消息可继续删除。 |
| P2 | 历史消息、最终回答、上游错误、附件 ID、工作区验证仍只识别双层包装。 | 统一使用记录解包函数，补读消息时间字段；单层/双层格式回归。 |
| P2 | 上游同步只返回旧历史时，管理页面的合并结果会丢掉本地正在生成或失败的尾部回答。 | 活跃/失败会话保留本地消息列表，防止旧快照抹去部分回答；新增回归。 |
| P2 | v1.4.5 真实图片验收发现，上游已完成的记录也会省略首条提问，导致刷新后看不到本地编辑的消息。 | v1.4.6 按共享消息 ID 保留缺失的本地消息和附件；涵盖首条、中间、末尾缺失、重复同步及先删回答再删旧提问的回归。原数据库内容未丢失。 |
| P2 | 会话被内存缓存淘汰后，改名和编辑没有先从 SQLite 恢复。 | 三种消息管理操作统一恢复后再修改；新增各操作的缓存淘汰回归。 |

## 重复部署

`scripts/deploy-release.sh` 接收版本、完整提交和发布包 SHA-256，安装根目录和服务 URL 由 `NOTION2API_ROOT`、`NOTION2API_URL` 提供。脚本先在独立临时目录启动打包程序验收，然后备份当前程序与数据、替换程序及静态页面、验证健康状态与资源一致性，失败时恢复程序及页面。既有发布目录不覆盖、不清理；数据备份单独存放，不混入发布包。

隔离验收使用随机临时 API 密钥和管理密码，避免示例配置的占位密钥阻止程序启动；启动失败会输出诊断信息。测试数据仅写入自动清理的临时目录。

## 后续修复：中文 Markdown 显示（v1.4.7）

用户截图与对应原始回复确认，`**时间点很敏感。**魁北克省…` 中粗体结束于中文标点，紧接中文正文。主聊天已使用 Markdown，但 CommonMark 的强调边界规则把这类星号当作普通文本；后台会话详情另有直接显示纯文本的遗漏。

三个消息入口统一使用 `MessageMarkdown`，通过 `remark-cjk-friendly` 的解析扩展兼容中文标点，并统一标题、列表、任务清单、引用、表格与代码块样式。保留原始消息和导出文本；代码、转义字符及安全链接策略不变。新增依赖的完整许可证随静态页面打包。

新增桌面/手机共 8 项浏览器回归，覆盖三个入口、中文强调、GFM 格式、代码与转义、外链安全、流式标记闭合、原文导出及两种主题的视口布局；已通过定向回归与生产构建，并检查桌面/手机实际截图。完整发布验证见对应 Release。
